The holes this vocabulary has

Three screens have no empty state at all. The install screen’s “Your website address” panel renders a titled panel with a description and nothing in the body when the origin list is empty. /calendar/setup’s Calendars and Services lists are bare <ul>s that render nothing when empty. The conversation thread renders an empty <ol> for a conversation with no messages.
There is no first-run or zero-data state anywhere. An empty queue, an empty tag list and an empty analytics range all render the same “nothing here” sentence a long-running site would see after a quiet week. Nothing distinguishes you have not set this up yet from nothing happened this week.
There is no unrecoverable-error state. When permissions fail to load the screen shows the “Checking your permissions…” Spinner forever: no timeout, no retry, no message. Two of the three /callback failures are dead ends whose only instruction is “reload”.
No offline or connection-lost state for the application itself. The realtime link has five states rendered in the workspace rail (see the Workspace card), but a REST call that fails because the browser is offline surfaces as an ordinary red Alert with the fetch’s own message.
