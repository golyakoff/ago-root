Input

One rule, three elements. Input, Textarea and Select are three components sharing one .ago-control rule — components.css gives them a single section banner — so a text field, a dropdown and a multi-line box are the same height, the same edge and the same focus treatment. Each takes an invalid boolean that becomes aria-invalid; Field passes it automatically when it has an error.

type="text"
::placeholder · --ago-ink-faint at opacity 1, because Firefox dims placeholders by default and would undo the measured contrast
type="date" — the native picker, on /search and all four reports
type="time" — the calendar’s working-hours and availability forms
type="number" — the billing seat count, the only one in the product
type="url" — the widget notice link and the FAQ entry point

States

:focus-visible · the global ring plus --ago-focus-halo
aria-invalid="true" · the edge turns --ago-danger
:disabled · --ago-surface-sunken
readonly — no distinct style at all
No read-only treatment. A readonly control renders identically to an editable one. The console has real read-only values (the site key, a configured origin) and styles them as .ago-install-value chips instead, which is a different thing in a different place.
No success or validated state on a control. aria-invalid is the only per-control feedback that exists; there is no green counterpart.
No character counter, and no live validation. The length limits that exist (canned responses, auto-reply text, knowledge base) are enforced on submit only, as a sentence in an Alert tone="danger" above the Save button. A field is never wrong while you are still typing in it.

The file variant, which is styled and unused

.ago-control--file exists and styles the native control’s own button. No screen uses it. The composer’s attach control is a visually-hidden native input driven by a ghost Button, and the widget does the same. The rule is in the stylesheet; the appearance is not on a screen.
