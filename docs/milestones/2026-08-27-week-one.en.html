02 — system view

Two products, one substrate, one dependency direction

Layered in the ArchiMate style — business actors on top, application components in the middle, shared technology underneath. Colour is the layer; solid arrows are real traffic today, dashed arrows are contracts designed but not yet built.

Business Application Technology real traffic today designed, not yet built

No two application hosts call each other synchronously — the broker is the only path between them, which is what makes each independently restartable. AGO Calendar consumes Ago.Platform.* exactly the way AGO Chat does, and never references it back: the dependency only runs downward.

As a separate file: the same model — actors, components, technologies and the relations between them — is included alongside this report in Archi format (.archimate), open it in Archi for the fully editable version.
03 — five minutes, live

What to actually click

Two browser tabs, no setup. Everything below runs against the real public deployment — one Postgres, one RabbitMQ, one Redis, on a single k3s node.

1
Open two tabssetup

Tab A: the widget on a real shop page. Tab B: the operator console, signed in.

2
Message as the visitorrealtimeconcurrency

Type in the widget. It lands in the operator's queue with no refresh — the SignalR fan-out and the compare-and-set assignment engine, both live.

3
Reply as the operatorrealtime

Answer from the console. It appears in the widget instantly, on the visitor's own connection.

4
Drop a file into the widgetstorage

Uploads straight to S3-compatible storage through a presigned URL — the bytes never pass through the API — and a thumbnail appears in the console.

5
Close the conversationshipped this week

A control that did not exist eight hours ago — the capacity it releases is what lets the operator take the next visitor.

6
Flip on the offline auto-reply, then go quietshipped this week

Toggle it in the console's site settings. Sign the operator out and message again as a new visitor — a scripted reply arrives labelled Automatic reply, never mistaken for a person.

7

The same widget, a second entry point: a full booking — service, time, phone, name — completing end to end against a local AGO Calendar. Proven; not deployed. Honestly labelled as such rather than staged.

04 — what's next

Three horizons

17 items sit ready and ordered in the queue. This is the shape of what's coming, grouped by how soon it's reachable rather than by stage number.

Next

queue head
14AGO Inbox channels

Soon customers will be able to reach an operator not just through the on-site chat but on MAX too — that's already submitted for approval. SMS and Telegram are next in line: SMS is waiting on picking a provider, and Telegram needs a real-world check first, on how reliably it actually works from Russia.

18Operator productivity

Making the operator's day-to-day easier: searching old conversations, handing a chat to a colleague, canned replies, personal notes and tags on conversations. Two of the five are already shipped — this week alone.

13Billing

First, invite teammates onto paid seats. Then take payment through ЮKassa — money only counts as received once the bank actually confirms it, never just because the browser bounced back to the site.

Then

unblocks soon
21Calendar becomes a chat module

So a visitor can book an appointment right inside the chat window, instead of being sent to another site. How chat and calendar will talk to each other is already worked out — what's left is fitting the actual booking steps to a real scenario.

16Personal data

A visitor's right to ask for their data to be deleted or handed back to them — not just a line in a privacy policy, but a button that actually works. Plus honest, in-widget notice about how their data is used.

15Retention & capacity

Automatic cleanup of old data so the server's disk doesn't fill up over time — plus an honest measurement of how fast it's actually filling, using real numbers going back to launch.
